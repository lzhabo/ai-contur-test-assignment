# Независимая интеграционная проверка

Запуск: `npm run test:integration`.

Используются настоящие LangGraph, SQLite, файловое хранилище и QuickJS. Облачные ответы заменены управляемыми mock-ответами; эти тесты **не подтверждают доступ к двум реальным моделям**. Каждый тест создаёт отдельный временный каталог. Сгенерированная функция исполняется только через изолированный CheckRunner; процессный helper — доверенная обвязка QA.

| Файл | Проверяемые требования |
|---|---|
| `artifacts.test.ts` | A-08/A-10: отсутствие результата до approval, точные скачиваемые байты и ZIP, повтор публикации, stale/reject, изменение/удаление файла, чужой ID, traversal и symlink родителей |
| `checks.test.ts` | A-08: слабые самопроверки против независимых границ, компиляция, отсутствие чтения внешнего TypeScript reference, мутация аргументов |
| `event-recovery.test.ts` | A-03/A-04/A-09: replay по курсору, дедупликация, восстановление после оборванной строки, запрет чтения/записи через symlink |
| `graph-recovery.test.ts` | A-02/A-03/A-04/A-08: durable interrupt, ограничитель цикла, неизвестный исход без скрытого retry, stop с поздним ответом, review не отменяет failed checks, ограниченный контекст |
| `process-restart.test.ts` | A-04: принудительный SIGKILL процесса на паузе и продолжение в новом процессе без повторного автора/ревьюера |

Окончательное заключение требует отдельного прогона на неизменяемом коммите координатора. Process restart на паузе пока не покрывает восстановление API-сервиса посреди незавершённого облачного вызова; проверяется отдельно после готовности сервиса. Контрольная строка доказывает отсутствие архива в переданном графом prompt, но сам по себе этот тест не доказывает отсутствие доступа реального Codex к файловой системе.

Браузерный сценарий подготовлен в `tests/e2e/product-flow.spec.ts`. Для отдельного автоматического запуска нужен mock backend с чистой папкой на 4318: `npm run test:e2e -- --config tests/e2e/playwright.config.ts`. Конфигурация использует установленный Chrome, один worker и вывод в `/tmp/two-model-loop-qa-playwright`. При текущей ручной проверке агент использует встроенный CUA по указанию координатора.
