# Интеграционные проверки

Запуск: `npm run test:integration`.

Используются настоящие LangGraph, SQLite, файловое хранилище, HTTP и QuickJS. Ответы Codex заменены управляемыми mock-ответами. Каждый тест получает отдельный временный каталог, который удаляется после закрытия ресурсов.

| Файл                               | Что проверяется                                                                                    |
| ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| `artifacts.test.ts`                | Подтверждение точной версии, байты файлов и ZIP, повтор публикации, подмена и безопасные пути      |
| `checks.test.ts`                   | Независимые граничные случаи, компиляция, запрет внешних ссылок и изменения аргументов             |
| `event-recovery.test.ts`           | История по курсору, отсутствие дубликатов, оборванная строка JSONL и символические ссылки          |
| `graph-recovery.test.ts`           | Пауза графа, лимиты, неизвестный исход, поздний ответ после остановки и объём контекста            |
| `service.test.ts`                  | Ключ создания, параллельные команды, устаревшее подтверждение, перезапуск и целостность результата |
| `http-validation.test.ts`          | Данные запроса, Origin, ключ создания, курсор, ошибки разбора тела и HEAD                          |
| `http-events.test.ts`              | SSE до и после переподключения, граница истории и новых событий, скачивание файлов                 |
| `http-frontend.test.ts`            | MIME, клиентские маршруты, отсутствующая сборка и ссылки за пределы dist                           |
| `process-restart.test.ts`          | SIGKILL на паузе и продолжение той же версии в новом процессе                                      |
| `service-process.test.ts`          | Сбой посреди вызова без скрытого повтора и конкуренция процессов за блокировку                     |
| `demo-observability.test.ts`       | Замоканная версия с намеренной ошибкой, цикл ревью и бюджет повторов                               |
| `checkpoint-observability.test.ts` | Журнал после сохранения SQLite без чувствительного содержимого                                     |

Сценарии показывают создание, решение, остановку и перезапуск непосредственно в тесте. Общие помощники в `../support/` готовят ресурсы и ожидают явно указанные условия. Процессные помощники в `support/` нужны только проверкам аварийного завершения.

Облачное подключение проверяется отдельно: `QA_REAL_CODEX=1 npm run test:e2e` и `npm run test:live-review`. Локальный E2E запускается командой `npm run test:e2e`; он сам поднимает mock-сервер с чистыми данными. Подробности — в [общей инструкции](../README.md).
