# Проверки

Команды выполняются из корня репозитория. Локальным HTTP-тестам нужен доступ к портам `127.0.0.1`.

| Команда                            | Что выполняется                                                                       | Ответы моделей                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `npm run check`                    | ESLint, TypeScript, unit/integration-тесты, сборка                                    | Mock там, где нужен вызов модели                                              |
| `npm run format:check`             | Форматирование кода и тестов                                                          | Нет вызовов                                                                   |
| `npm run test:integration`         | Совместная работа модулей, HTTP, диск, SQLite и процессы                              | Mock                                                                          |
| `npm run test:e2e`                 | Создание задачи, роли, перезагрузка страницы, подтверждение и скачивание ZIP в Chrome | Mock                                                                          |
| `npm run test:e2e:auth`            | Выход до создания и во время ревью, повторный вход и продолжение сохранённой задачи   | Исполняемый mock CLI; настоящий браузер, HTTP, адаптер CLI и хранилище        |
| `QA_REAL_CODEX=1 npm run test:e2e` | Тот же браузерный путь через Codex                                                    | Настоящие модели                                                              |
| `npm run test:live-review`         | Возврат замечаний автору, исправление, повторное ревью                                | Первая версия замокана с намеренной ошибкой; следующие три ответа — настоящие |
| `npm run check:full`               | `check`, форматирование, login/logout, оба модельных E2E и смешанная проба            | Mock, real, mixed                                                             |

E2E сам собирает интерфейс, запускает сервер на `127.0.0.1:4318` и удаляет временные данные после закрытия. Порт меняется через `QA_E2E_PORT`. Требуется установленный Google Chrome; уже работающий сервер не переиспользуется.

Для настоящих моделей нужны Codex CLI и авторизация из [README](../README.md#запуск). Вызовы расходуют лимит аккаунта. Если CLI, сеть или лимит недоступны, команда завершится ошибкой; причину нужно отдельно указать в отчёте. Автоматического перехода на mock нет.

## Какие правила проверяются

| Область                   | Основные сценарии                                                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `unit/`                   | Общие схемы и настройки, ограничения кода, QuickJS, файлы версий, протокол CLI, кеш и отображение клиента.                       |
| `integration/`            | Цикл ревью, бюджеты, остановка, неизвестный исход, идемпотентность команд и подтверждение точной версии.                         |
| `integration/` — хранение | Хеши файлов и ZIP, подмена путей, оборванная строка истории, повторная доставка SSE, блокировка папки, SIGKILL и восстановление. |
| `e2e/`                    | Пользовательский путь через браузер и действующий HTTP-сервер.                                                                   |
| `live/`                   | Исправление известной ошибки настоящими ревьюером и автором. Отчёт указывает источник каждого ответа.                            |

Mock управляет ответами модели; Express, LangGraph, SQLite, файловое хранилище и QuickJS в соответствующих тестах работают настоящие. Локальный PASS не подтверждает доступность облачного Codex.

## Проверка подключения и авторизации

- `unit/codex/cli-port.test.ts`: версия CLI, вход из stdout/stderr, отсутствие бинарника/входа, несовместимость, таймаут и отмена проверки, предел вывода, отсутствие утечки ключа; известные 401/403/429 и неизвестный сетевой исход. CLI заменён исполняемым mock-скриптом; процессы настоящие.
- `integration/connections.test.ts`: диагностика по HTTP; запрет создания, подтверждения и повтора без входа до записи и новой попытки; вход после отказа; выход после успешной проверки; доступность истории и отказа от версии; известная ошибка входа во время выполнения. Проверка входа и ответы модели замоканы, сервер, диск и SQLite настоящие.
- `unit/web/connections.test.tsx`: инструкция входа, блокировка формы и прямого submit, повтор после входа, потеря сервера после успешной проверки, обновление каждые 15 секунд, честное обозначение mock и непроверенного облака. HTTP замокан.
- `integration/auth-resume.test.ts`: продолжение каждой роли после ошибки входа, сохранение контекста и версии, перезапуск, запрет повтора без входа, остановка, бюджет, двойная команда и старая задача с известной ошибкой авторизации. Codex замокан; граф, SQLite и файлы настоящие.
- `unit/web/task-resume.test.tsx`: кнопка продолжения после входа, сохранение задачи, отсутствие автоматического запуска, повторный отказ и отдельное предупреждение о неизвестном исходе. HTTP замокан.

Эти регрессии не подтверждают доступ к облаку текущего аккаунта. Для него отдельно запускаются real E2E и модельные пробы.

`npm run test:e2e:auth` проверяет переход login/logout через браузер и настоящий `CodexCliPort`: исполняемый mock CLI управляет наличием входа и ответами модели. Проверка воспроизводит запуск до очередного опроса подключения, отказ без создания задачи и вызова модели, сохранение текста, повторный вход и один запуск с прежним ключом. Сервер использует временные данные и отдельный порт `4328` (`QA_AUTH_E2E_PORT`); личная авторизация не затрагивается. Отдельный сценарий прерывает ревью ошибкой входа: сохранённая версия остаётся доступна, после login и ручного продолжения повторяется только ревью, затем задача доходит до ZIP. Этот прогон не подтверждает настоящий цикл входа/выхода или доступ к облаку.

## Ручные mock-сценарии

```sh
APP_CODEX_MODE=mock APP_MOCK_SCENARIO=review_once APP_DATA_DIR=.local-data/mock-review npm start
```

| Сценарий      | Поведение                                                                         |
| ------------- | --------------------------------------------------------------------------------- |
| `happy`       | Первая версия проходит проверки и ревью.                                          |
| `review_once` | Замоканная версия с намеренной ошибкой, замечание, исправление и повторное ревью. |
| `review_loop` | Повторные замечания до исчерпания бюджета.                                        |
| `no_response` | Ожидание до отмены или таймаута.                                                  |
| `slow`        | Задержанные ответы для проверки ожидания и остановки.                             |

## Тестовые данные

- `fixtures/merge-intervals.json`: 23 независимых случая для объединения интервалов, включая неверные входы и проверку изменения аргументов.
- `fixtures/weak-self-tests.json`: замоканная версия с намеренной ошибкой и два слабых теста, которые пропускают её; независимые случаи обнаруживают дефект.

Оба файла читаются интеграционными проверками и смешанной модельной пробой. `source` в fixture — строка тестовых данных; полученный код исполняется в QuickJS. Проверка структуры данных:

```sh
python3 tests/fixtures/validate.py
```

## Пробы отдельных механизмов

`test:workflow-probe` проверяет совместимость LangGraph/SQLite на собственном минимальном графе. Роль автора имитируется записью счётчика. Первый процесс сохраняет состояние до подтверждения, второй продолжает без повторного увеличения счётчика. Восстановление приложения проверяется integration-тестами.

```sh
probe_dir="$(mktemp -d "${TMPDIR:-/tmp}/kontur-workflow-probe.XXXXXX")"
npm run test:workflow-probe -- start "$probe_dir/checkpoints.sqlite" "$probe_dir/author-calls.txt"
npm run test:workflow-probe -- resume "$probe_dir/checkpoints.sqlite" "$probe_dir/author-calls.txt"
rm -r -- "$probe_dir"
```

Оба процесса выводят `authorCalls: 1`; второй — `phase: "complete"`.

Другие ручные пробы: `node --import tsx tests/unit/checks/quickjs.probe.ts` проверяет изоляцию и лимиты QuickJS; `node tests/unit/codex/cancel-process-group.probe.mjs` — отмену группы процессов. `node --import tsx tests/unit/codex/live-candidate.probe.ts` вызывает настоящего автора; `QA_CODEX_BINARY` задаёт путь CLI для этой пробы.

## Как читать и менять тесты

Существенные входы, действия и ожидаемые значения находятся в самом тесте и разделены пустыми строками. `support/` готовит временные ресурсы и очистку; сценарий остаётся видимым. Название сообщает проверяемое правило, комментарий объясняет неочевидный механизм.

Датированные результаты и способ получить прежние доказательства из Git — в [PROJECT_HISTORY.md](../PROJECT_HISTORY.md).
