# Доказательства сквозных прогонов

26.09.2026: `live-review-feedback.json` — отчёт отдельного живого probe. Первая версия была **внедрённым дефектным fixture**, не ответом Sol; её два самотеста прошли, три независимых граничных случая провалились. Настоящий Luna через Codex CLI вернул `changes_requested` с конкретным контрпримером `[[1,3],[2,4]] → [[1,4]]`; настоящий Sol получил замечания и создал новую версию; независимые случаи прошли, повторный настоящий Luna ответил `approved`. Граф сохранил две версии и четыре попытки, из них три облачные; итог `awaiting_approval`, результата нет. Полная папка прогона: `.local-data/live-review-feedback-jAjq99`, задача `6ce56af2-66e2-4c3d-8129-a531a37076bc`. Это проверка живого цикла ревью и исправления, но она не доказывает, что Sol самостоятельно написал первую ошибочную версию.

24.09.2026, локальный MacBook. Это сохранённые ответы read-only API после действий координатора в настоящем встроенном браузере (CUA), а не сгенерированные ожидаемые результаты. Уровень независимости: сценарии подготовлены QA; UI выполнял координатор, поскольку браузерный инструмент QA не предоставлял доступную поверхность.

- `real-paused.json`: реальные author Sol и reviewer Luna через сохранённый Codex login; 9 тестов, версия `1c456ee4-bcee-43d0-b3ca-d087fbdf6ffa`, два вызова. Backend остановлен и запущен снова; версия и счётчик сохранились. `result` отсутствует. Финальное подтверждение отдельно запрошено у пользователя после отказа автоматической проверки разрешений; этот снимок не доказывает реальную публикацию.
- `ui-cycle-limit.json`: явный fake review_loop, три версии и шесть вызовов, остановка «Исчерпан лимит версий функции»; UI не выдаёт это за успех.
- `ui-repeat-rejected.json`: второй последовательный запуск того же текста без reload получил новый ID. Первый ID `ba0add6d-6cb3-48ca-9899-d2fa12d125c3`, второй `cf73baf3-77f3-487e-bfa0-3c552930db64`. Отказ через UI остановил второй запуск без публикации.

Дополнительно наблюдалось в браузере: no_response (`f1d8a62c-9ff9-4879-8144-79fe62520537`) показал возраст 0→14→45 секунд и последнее fake.started. После TERM/restart та же задача имела unknown_outcome и один вызов, без автоматического повтора. Кнопка остановки завершила её. Файлы этой тестовой истории сохранены в игнорируемой `.local-data/ui-no-response`.

Ранний полный fake review_once (`a06b9131-a574-4f6f-9a26-d605fb5d1dc0`) прошёл две версии, четыре вызова до подтверждения и пятый после него; показал папку результата и копирование пути. Хеши solution.ts `6bb75eb772846e86513fc5926ae1760f70484d62e59419c41843b329d93ce894`, solution.test.ts `e9207e79b1f79b16241f657b784910df6ecc97b2e4ece1e596d4116dbffcbfe3`. Полный fake-прогон не является доказательством третьего реального облачного вызова.

Приложение наблюдает заданные CLI model IDs и жизненный цикл процесса. CLI не предоставляет независимое подтверждение backend model ID; самодекларация модели не используется как доказательство. Основной реальный прогон начат на `343f6f4`; восстановление выполнено после исправлений, закреплённых в `a1ed4e2`.

Ссылка ZIP завершённого fake-прогона нажата через CUA, получено событие download. Соответствие содержимого ZIP одобренным файлам проверено отдельно интеграционными тестами. Browser tool вернулся с большой задержкой; она не измеряет скорость HTTP сервера и не считается свойством приложения.
