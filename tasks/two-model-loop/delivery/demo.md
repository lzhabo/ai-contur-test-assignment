# Сценарий демонстрации — 20 минут

Сценарий подготовлен для оператора. Отдельные шаги проверены в браузере и интеграционных тестах (verification.md); непрерывная 20-минутная репетиция с проверяющим ещё не проводилась. Основной сценарий использует реальные модели; намеренные сбои воспроизводятся управляемым адаптером и явно подписываются как имитация.

| Время | Действие оператора | Что проверяющий должен увидеть |
|---|---|---|
| 0–2 мин | Запустить приложение по одностраничному хендоффу с пустой папкой данных | Один локальный адрес, пустая история, готовность Codex |
| 2–7 мин | Создать задачу объединения интервалов; посмотреть автора, проверки и ревью | Два разных настроенных model ID; сообщения передаются автоматически; файлы пока черновые |
| 7–9 мин | Просмотреть функцию, тесты и замечания, подтвердить текущую версию | Третий агент вызывается после решения; результат совпадает с одобренными байтами; скачивание и отдельная папка |
| 9–11 мин | Включить сценарий непрерывных замечаний ревьюера | Счётчик достигает лимита; работа останавливается с причиной; это не успешное завершение |
| 11–13 мин | Включить сценарий отсутствия ответа | Кто ожидает, что фактически известно о попытке и сколько прошло времени; нет ложного успеха |
| 13–16 мин | Перезапустить backend на паузе подтверждения; отдельно показать неизвестный исход незавершённого вызова | Та же задача, версия и бюджет; нет повторного автора на паузе; повтор неизвестного вызова требует явного действия |
| 16–18 мин | Показать ограниченный ввод следующего вызова и папки данных | Ввод содержит актуальные данные, а не всю переписку; SQLite хранит состояние, файлы лежат отдельно |
| 18–20 мин | Показать историю Git, журнал решений и настоящие переписки; ответить на вопросы | Что изменили после возражения, что доказано и что осталось нерешённым |

Время ответа облака непредсказуемо. Подготовленные журналы удачных реальных прогонов нужны как запасное доказательство, но не выдаются за текущий живой прогон. Если облако не ответило во время демонстрации, интерфейс должен показать это как отсутствие ответа.

## Команды и подготовка

Из корня проекта, после `npm ci`. Основное приложение: `npm start` → http://127.0.0.1:4317. Папку с историей сохраняйте; используйте новый `APP_DATA_DIR` для чистого повтора. Два управляемых сценария можно поднять заранее в отдельных терминалах:

```sh
APP_CODEX_MODE=fake APP_FAKE_SCENARIO=review_loop APP_DATA_DIR=.local-data/demo-loop APP_PORT=4318 npm start
APP_CODEX_MODE=fake APP_FAKE_SCENARIO=no_response APP_DATA_DIR=.local-data/demo-wait APP_PORT=4319 npm start
```

Для показа доработки по замечаниям: `APP_FAKE_SCENARIO=review_once` с новой папкой и свободным портом. Во всех fake-окнах видна надпись «Тестовый режим · без облака».

В `no_response` создайте задачу, дождитесь предупреждения после 30 секунд, покажите растущий возраст и последнее наблюдение. Для демонстрации неизвестного исхода остановите backend во время ожидания, запустите снова с той же папкой: повтор не должен происходить без нажатия «Повторить неизвестный вызов». Для окончательного завершения нажмите «Остановить». Ждать все 180 секунд на демонстрации необязательно; таймаут отдельно проверяется автоматическими сценариями.

На паузе реального задания запишите ID версии и счётчик, перезапустите backend, откройте ту же задачу: автор и ревьюер не вызываются заново. Подтверждение делает сам оператор. Файлы и ZIP должны совпасть с одобренной версией.

Запасное доказательство: журнал реального прогона в delivery/evidence (когда он завершён), E0/E2 отчёты в tests/unit/codex. Это записи прошлых проверок, не замена живого ответа. Формулируйте идентичность моделей точно: приложение запустило Codex с разными model IDs; независимого backend model ID CLI не возвращает.
