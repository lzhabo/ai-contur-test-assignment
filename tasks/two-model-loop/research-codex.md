# Исследование: Codex как доступ к двум моделям

Дата: 24.09.2026. Основание: согласованное ТЗ 0.3. Это исследование, не подтверждение работоспособности будущего приложения.

## Вывод

Требуемый путь поддерживается на уровне интерфейсов: локальный Codex CLI умеет использовать сохранённый вход ChatGPT и выбирать модель для отдельного запуска. Предварительная рекомендация — обращаться к установленному Codex через `exec --json` из TypeScript. Не извлекать токены и не использовать их как ключ к произвольному API.

## Факты из документации

- Codex поддерживает вход ChatGPT для доступа по подписке и API key как отдельный способ. Вход кешируется и повторно используется. Это разные режимы доступа; наличие входа не доказывает доступность каждой модели. [Authentication](https://learn.chatgpt.com/docs/auth).
- Неинтерактивный `codex exec` использует сохранённую CLI-аутентификацию. JSONL выдаёт события начала, завершения и ошибки; JSON Schema задаёт структуру финального ответа. Это полезная основа адаптера, но бизнес-состояние доставки/ожидания нужно хранить отдельно. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).
- Есть официальный TypeScript SDK `@openai/codex-sdk`, Node.js 18+, с созданием и возобновлением сессий. Сам факт поддержки resume не доказывает ограниченность входного контекста. [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk).
- App Server предоставляет JSON-RPC, `model/list`, выбор модели и события; доступные модели зависят от клиента/аккаунта. Документация рекомендует SDK для автоматизации; App Server рассчитан на более глубокую интеграцию. [App Server](https://learn.chatgpt.com/docs/app-server).

## Варианты подключения

| Вариант | Плюсы для задачи | Цена/неизвестное | Вывод |
|---|---|---|---|
| TypeScript → `codex exec --json` | Уже установлен; явная модель; события; процесс можно ограничить по времени | Собственный разбор событий и завершение дочернего процесса; проверить начало обмена и ошибки на реальном прогоне | Предварительно предпочитаем для малого контура |
| TypeScript → Codex SDK | Официальная библиотека, удобное управление сессиями | Новая зависимость; зафиксировать версию и проверить точные настройки модели, процесса и аутентификации | Хорошая альтернатива, если ручной адаптер CLI становится сложнее |
| TypeScript → App Server | RPC, каталог моделей, богатые события и approvals | Больше протокола и жизненного цикла; локальный запуск сейчас ограничен служебной записью | Для первой версии избыточен |

## Что нельзя объявлять доказанным

1. Два успешных реальных запуска под текущим аккаунтом: пока не выполнялись. Кэш моделей — свидетельство каталога, не успешной генерации.
2. Поддержку моделей сторонних поставщиков через вход Codex: исследование её не устанавливает, ТЗ разных поставщиков не требует.
3. Ограничение всего контекста: размер нашего prompt не включает автоматически системные инструкции, AGENTS.md и дополнительные чтения инструментами. В проектном решении нужна контролируемая рабочая папка без полного архива и явный учёт того, что измеряется.
4. Доставку в удалённую модель по событию запуска процесса. Можно доказать приём локальным адаптером, отдельно показывать начавшийся ход и полученный ответ; неподтверждённый этап нельзя выдавать за подтверждённый.

## Предложение о моделях и проверке реализуемости

Кандидаты: автор и применяющий агент — `gpt-6-sol`; ревьюер — `gpt-6-luna`. Это две разные модели из локального каталога, не рекомендация, основанная на сравнительном тесте качества. Назначения настраиваемые, их окончательный выбор не сделан.

В будущий план включить раннюю проверку: два коротких реальных вызова с явно заданными моделями, использованием сохранённой аутентификации, без API-ключей и без смены режима оплаты. Проверить журнал событий, выход по ошибке/таймауту, прочитанный контекст и лимиты аккаунта. При недоступности одной модели явно остановиться и выбрать другую из реально доступных, не подменять молча обе роли одной моделью.
