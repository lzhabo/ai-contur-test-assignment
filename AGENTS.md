# Работа над задачами

Основной агент в диалоге — координатор. Он общается с человеком по-русски, хранит согласованные решения и отвечает за общий результат. Подагенты исполняют только выданное им задание; этот документ не превращает каждого подагента в координатора.

При запуске или продолжении многоэтапной задачи прочитай `development-process.md` и документы соответствующей задачи в `project-history/<task-id>/`. Используй параллельных подагентов для независимых частей исследования, реализации и проверки. Простые вопросы и мелкие изменения выполняй непосредственно.

Роли описаны в `.codex/agents/*.toml`. Если текущий клиент не загрузил именованные роли, прочитай нужный файл и передай его `developer_instructions` обычному подагенту как задание. Сообщи об использовании такого способа; не утверждай, что роль зарегистрирована автоматически.

До делегирования укажи задачу, входные документы, область разрешённых изменений, зависимости, рабочую директорию и ожидаемое доказательство готовности. Подагенты возвращают результат координатору; общие документы состояния обновляет координатор.

Код проекта располагается в этой рабочей папке по структуре выбранного стека. Материалы в родительской папке не являются входными данными задачи, пока человек явно не включит их в её контекст.


# Код и тесты

При реализации или ревью этой переработки читай `project-history/architecture-rework/plan.md` и `readability.md` в той же папке. Последние явно согласованные решения пользователя имеют приоритет над историческими предложениями.

- У каждой новой, перенесённой или переписанной функции, метода и callback есть короткое объяснение на русском: назначение, основное действие и существенные побочные эффекты. Комментарии обновляются вместе с поведением.
- Модули делятся по обязанностям; объём файла служит поводом для ревью. Используй обычное форматирование и именованные экспорты production-кода.
- Компоненты клиента отображают данные; запросы находятся в api, серверные данные и подписки — в hooks. Общие схемы в shared не импортируют серверный код или Node.js.
- В тесте видны существенные входные данные, действия и ожидаемые значения/ошибки. Эти этапы разделяются пустыми строками. Помощники скрывают только техническую подготовку и очистку.
- Тестовые подмены называются mock. Подставленный дефект называется «замоканная версия с намеренной ошибкой». Смешанные проверки явно указывают происхождение каждого ответа.
- Для проверки изменений запускай `npm run check`; E2E и реальные модельные прогоны фиксируй отдельно. Фактические команды находятся в package.json.
