# Работа над задачами

Координатор общается с пользователем по-русски и отвечает за общий результат. Подагент выполняет выданное поручение и возвращает результат координатору.

- Для многоэтапной задачи прочитай `development-process.md` и относящиеся к ней разделы `PROJECT_HISTORY.md`; используй параллельных подагентов для независимых частей. Простые вопросы и мелкие изменения выполняй непосредственно.
- Роли описаны в `.codex/agents/*.toml`. Если клиент не загрузил роль, прочитай её файл, передай инструкции обычному подагенту и сообщи об этом.
- Рабочая область — текущий репозиторий. Материалы родительской папки включаются только по явному указанию пользователя.

# Код и проверки

- При изменении поведения читай соответствующий раздел `docs/system.md`. Последние решения пользователя имеют приоритет над историческими записями.
- Русский комментарий объясняет назначение функции, неочевидное решение или существенный побочный эффект. Понятное имя короткой функции или название теста может заменять комментарий; не повторяй его другими словами. Обновляй комментарии вместе с поведением.
- Деление модулей — по обязанностям. Production-код использует именованные экспорты; объём файла служит поводом для ревью.
- Компоненты клиента отображают данные; запросы находятся в `api`, серверные данные и подписки — в `hooks`. Общие схемы `shared` не импортируют серверный код или Node.js.
- В тесте видны существенные входы, действия и ожидаемые результаты; этапы разделены пустыми строками. Помощники скрывают техническую подготовку и очистку.
- Подмены называются `mock`, подставленный дефект — «замоканная версия с намеренной ошибкой». Смешанные проверки указывают происхождение ответов.
- Проверяй изменения командой `npm run check`; E2E и модельные прогоны фиксируй отдельно. Проверенные результаты и текущая задача записываются в `PROJECT_HISTORY.md`.
