24.09.2026. План независимой проверки, подготовленный до реализации. Основание: `brief.md` v0.4 (A-01–A-10), принятая пользователем архитектура и уточнение об отдельной папке результата каждой задачи; `research-langgraph-comparison.md`. Продуктовые уточнения уже перенесены в ТЗ 0.4. Этот документ не объявляет реализацию или проверки выполненными.

Фактические статусы и ограничения исполнения этой матрицы находятся в [verification.md](verification.md). План ниже не является отчётом об успешной приёмке.

## Уровни и условия проверки

- **I — интеграция с управляемым адаптером.** Настоящий граф, файловый SQLite-checkpointer, файловые артефакты и API; вместо облака — предсказуемый процесс, умеющий отвечать, зависать, создавать дочерний процесс и завершаться ошибкой. Здесь воспроизводим сбои и точные границы остановки.
- **L — реальные модели.** Установленный Codex и действующая авторизация; автор и ревьюер с двумя различными подтверждёнными ID моделей, применяющий агент на одной из них. Mock-прогон не заменяет этот уровень.
- **B — браузер.** Реальный frontend и backend; управляемый адаптер для устойчивых негативных сценариев и отдельный сквозной прогон с реальными моделями.
- **D — комплект сдачи.** Проверка материалов, истории работы, хендоффа и демонстрации.

Итоговый QA проходит на неизменяемом объединённом коммите, указанном координатором. До этого допустима подготовка сценариев, но не заключение о готовности. Каждый прогон использует свой каталог данных и, когда нужен HTTP, выделенный порт; предлагаемый QA-порт — 4318. После исправления production-кода владельцем координатор выдаёт новый коммит, QA повторяет затронутые проверки.

## Негативные сценарии и тестовые данные

| ID | Воздействие | Ожидаемый результат |
|---|---|---|
| N-01 | Постоянное отрицательное ревью; остановка backend перед последней доступной попыткой | Общий лимит не сбрасывается, новых вызовов после исчерпания нет; это не успех задачи |
| N-02 | Зависание без первого события / после подтверждения адаптера | Разные известные этапы; нет вымышленного «доставлено»; возраст считается от сохранённого времени, включая перезапуск |
| N-03 | Закрыть вкладку, затем отдельно принудительно завершить backend | Закрытие вкладки не останавливает выполнение; авария backend приводит к восстановлению, а не новой задаче или ложному успеху |
| N-04 | Создать историю больше бюджета входа; вставить в ранний архив уникальную контрольную строку | Вход продолжения укладывается в бюджет; контрольная строка отсутствует, полный архив недоступен процессу модели; чрезмерный актуальный ввод обрабатывается явно |
| N-05 | Перезапуск на `interrupt`, решение после открытия приложения | Та же версия и пауза; автор/ревьюер повторно не вызываются из-за ответа человека; до решения публикации нет |
| N-06 | Два одинаковых подтверждения, подтверждение старой версии, подтверждение после отказа/остановки | Не больше одной публикации; устаревшее/недопустимое решение отклонено; подтверждение связано с ID версии и хешами |
| N-07 | Нажать «Остановить», когда адаптер завис и породил дочерний процесс | Группа процессов завершена; поздний ответ не возобновляет граф; новых вызовов нет, остановка сохраняется |
| N-08 | Убить backend после записи части результата и до checkpoint успешной публикации | Частичный результат не выдан за готовый; сверка с подтверждённой версией обеспечивает однозначное завершение/ошибку без публикации другой версии |
| N-09 | `../`, абсолютный путь, симлинк наружу, чужой task/artifact ID в операциях записи и скачивания | Чтение/запись ограничены папкой задачи и разрешёнными артефактами; файл за пределами области не затронут |
| N-10 | Изменить/удалить версию после ревью; отдельно — после подтверждения, до публикации | Несовпадение обнаружено, публикация остановлена, старое подтверждение не разрешает новые байты |
| N-11 | Сгенерированная функция неверна на границе, хотя её собственные тесты проходят | Независимые тесты выявляют дефект; положительное ревью или самопроверка модели не подменяют проверку логики |
| N-12 | Потеря SSE, повторная доставка событий, переподключение на другой этап и после рестарта backend | Экран сходится с сохранённым состоянием без дублей; недостающие долговечные события доступны; потерянные промежуточные фрагменты не выдаются за полную историю |
| N-13 | Авария после фиксации намерения вызова, во время запуска Codex и сразу после внешнего ответа | До внешнего эффекта существует сохраняемый ID попытки; после аварии неизвестный исход виден явно. Повтор следует ограниченной политике, не расходует бесконечный бюджет |

Для основной функции предлагается объединение замкнутых интервалов: пустой список, один интервал, непересекающиеся, пересекающиеся, вложенные, соприкасающиеся, отрицательные границы, вход не отсортирован, отсутствие мутации входа. Точные правила некорректных интервалов закрепить в тексте примера до тестирования. Второй и третий примеры также получают однозначные правила. Проверки генерируемого кода используют чистые функции и фиксированные данные без сети, пользовательских файлов и секретов. Механизм ограниченного выполнения тестов проверяется отдельным зависающим тестом.

## Контракты, нужные до реализации

1. Установить источник каждого подтверждения доставки. Название события Codex не интерпретировать сильнее его документированной семантики; сохранить источник и время.
2. Сначала надёжно сохранить ID/номер/время попытки и зарезервировать бюджет, затем запускать внешний процесс. Проверить режим сохранения выбранного LangGraph: асинхронный checkpoint не должен оставлять эту запись только в памяти перед побочным эффектом. Не писать второй координатор.
3. Определить минимальные долговечные события и reconnect-контракт. Streaming сам по себе не доказывает восстановление пропущенных событий; допустимо отдельно считать промежуточные текстовые фрагменты временными и ясно обозначить это.
4. Зафиксировать численные лимиты обмена, времени вызова/отмены, контекста и вывода процесса; точные реакции на отказ, аварийный исход и повреждённый артефакт. Пока значений нет, соответствующая граница теста не определена.
