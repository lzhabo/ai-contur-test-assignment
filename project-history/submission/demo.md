# Демонстрация Контура — около 20 минут

Цель: показать путь от задания до сохранённой версии, исправление после ревью, контроль человека и доказательства решений. Оставить время на вмешательство проверяющих. Актуально для кода `main` на `f537ce4`; названия кнопок и символы сверены с исходниками.

## Подготовка до встречи

1. Пройти [handoff](handoff.md): Node.js 26+, `npm ci`, версия и вход Codex. Выполнить `npm run check`, записать фактический результат. Для браузерных тестов нужен установленный Google Chrome; `npm run test:e2e` использует порт 4318. Эти проверки завершить до показа.
2. Открыть репозиторий в редакторе, файлы из таблицы ниже, журнал решений и выбранные исходные переписки. История разработки: `git log --graph --oneline --all -25`.
3. Запустить два терминала и две подписанные вкладки. Папки ниже должны быть новыми для репетиции/показа; для следующего прогона выбрать новые имена. Для восстановления использовать прежнее имя. Настоящий и mock-серверы имеют разные каталоги и порты.

**Терминал A — настоящий Codex:**

```sh
APP_CODEX_MODE=real APP_DATA_DIR=.local-data/demo-real APP_PORT=4317 npm start
```

Вкладка A: [http://127.0.0.1:4317](http://127.0.0.1:4317).

**Терминал B — воспроизводимый возврат на исправление:**

```sh
APP_CODEX_MODE=mock APP_MOCK_SCENARIO=review_once APP_DATA_DIR=.local-data/demo-mock APP_PORT=4319 npm start
```

Вкладка B: [http://127.0.0.1:4319](http://127.0.0.1:4319). Проверить видимую надпись «Тестовый режим». В этом сценарии **все ответы замоканы**, включая замечание и исправление. Первый код — **замоканная версия с намеренной ошибкой**.

4. Держать рядом ранее сохранённые доказательства: `project-history/architecture-rework/evidence/e2e-real.txt`, `mixed-review.json`, `real-processes.json`. Это исторические прогоны с указанной в verification версией, а не результаты сегодняшнего показа.

## Если реальный вызов задержался или упал

- На 30-й секунде показать сообщение ожидания. Переключиться на код, пока запрос работает. Если к 5:30 нужной паузы нет, нажать «Остановить», зафиксировать видимую причину/последнее наблюдение и продолжить основной путь в B. Тогда первую задачу B **подтвердить**, чтобы показать ZIP; для отказа создать вторую mock-задачу. Прямо сказать, что завершённый показ сегодня прошёл в mock.
- При ошибке доступа проверить в терминале `/opt/homebrew/bin/codex login status` и `--version`. Повтор требует отдельного решения и расходует новую попытку. Не переключать адаптер у сохранённой настоящей задачи; продолжать показ в другой папке данных.
- При `unknown_outcome` показать «Повторить неизвестный вызов» и предупреждение о новой попытке. Автоматического повтора нет. Если живой повтор не нужен для показа, оставить задачу на паузе или остановить.
- Если нет времени на настоящее исправление модели, открыть `mixed-review.json`: первая версия замокана с намеренной ошибкой, затем настоящий ревьюер, настоящий автор и настоящий ревьюер — три облачных вызова. Это **смешанное** историческое доказательство. Текущий `review_once` полностью замокан.
- Аварийное завершение backend через SIGKILL не включать в основной показ: после него может остаться процесс Codex. Для объяснения использовать сохранённый отчёт с точными границами проверки.

### Запасная демонстрация остановки, 1–2 минуты

Если спрашивают об отмене, заменить ею часть экскурсии по коду. После завершения/отклонения задачи B остановить её сервер и запустить в том же терминале отдельный сценарий:

```sh
APP_CODEX_MODE=mock APP_MOCK_SCENARIO=no_response APP_DATA_DIR=.local-data/demo-stop APP_PORT=4319 npm start
```

Открыть главную страницу B, создать задачу и нажать «Остановить» во время ожидания. Показать статус остановки и отсутствие ZIP. Это проверка отмены на управляемом mock-ожидании; подтверждение остановки настоящего процесса находится отдельно в `real-processes.json`.

## После показа

Сохранить ID показанных задач и фактические исходы: real/mock/mixed, была ли доработка, подтверждение, отказ или ошибка. Остановить свои серверы через Ctrl+C. Сохранённые папки данных позволяют воспроизвести историю; записи успешного прошлого прогона не заменяют результат текущего.
