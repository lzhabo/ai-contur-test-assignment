# Журнал решений

23–28 сентября 2026. Короткая ретроспектива по обсуждениям и истории репозитория. Это пересказ; исходные сообщения для сдачи находятся в [трёх переписках](conversations/README.md). Даты и конкретные задачи Codex перечислены в [источниках](sources.md). «Предлагали» не означает «реализовали».

## Объём и архитектура

1. **Неясное «локально» → облачные модели через Codex.** Уточнили, что локально работают приложение и хранилище, а модели вызываются в облаке. Поднимать модели на MacBook не стали. [S1, 24.09](sources.md#s1).
2. **Два агента → три роли на двух моделях.** Согласовали автора, ревьюера на другой модели и применяющего агента; третья отдельная модель не нужна. Ограничили задачу одной чистой синхронной TypeScript-функцией с JSON-входом/выходом. [S1](sources.md#s1).
3. **Автоматическое применение после ревью → подтверждение человека.** На предложение модели записывать результат сразу пользователь ответила: «Сначала спросить моё подтверждение». Применяется только выбранная версия с проверкой её хеша. [S1](sources.md#s1).
4. **Свой координатор + SQLite → LangGraph + SQLite.** Модель первоначально рекомендовала написать координатор. Пользователь возразила: готовые сохранение, пауза и восстановление уменьшают собственную инфраструктуру. После повторного сравнения рекомендацию изменили. Agents SDK исключили из дальнейшего сравнения как избыточный для принятого объёма. [Переписка 1](conversations/01-langgraph-choice.md).
5. **Неясное «SQLite-хранилище» → готовый SqliteSaver.** После вопроса пользователя уточнили, что сохранение состояния предоставляет официальный checkpointer LangGraph. Свой механизм checkpoints не пишем; формат состояния, вызовы моделей и правила переходов определяет приложение. [S1](sources.md#s1), [исходный фрагмент](../two-model-loop/delivery/conversations/02-sqlite-clarification.jsonl).
6. **Текстовый интерфейс → локальное веб-приложение.** Первоначальное минимальное ТЗ предлагало текстовый интерфейс. При обсуждении продукта согласовали браузерную страницу и один Node.js backend: задание, примеры, ход работы, код и решение пользователя. [S1](sources.md#s1).
7. **Внутренние шаги в пользовательском пути → действия человека.** Пользователь указала, что описание смешивает действия пользователя и работу агентов. Путь переписали: открыть → добавить задачу → ввести текст/выбрать пример → запустить → посмотреть работу → подтвердить/отклонить → получить файлы. [Переписка 2](conversations/02-user-journey-and-artifacts.md).
8. **Неопределённая выдача результата → папка каждой задачи и скачивание.** От изменения произвольного существующего проекта отказались для первой версии. Код и тесты лежат в файловых версиях и `result/`; состояние графа хранит ссылки и хеши. [Переписка 2](conversations/02-user-journey-and-artifacts.md).

## Проверки и наблюдаемость

9. **Быстрый успешный прогон → видимая история процесса.** Пользователь не увидела промежуточного ревью и запросила граф, логи и более сложный пример. Добавили граф этапов, историю замечаний по версиям, диагностику изменений состояния и задачу расчёта корзины. Сложный промпт не гарантирует замечаний реальной модели. [S1, 25.09](sources.md#s1); commit `6bfa3de`.
10. **«Показали цикл» → проверили, кто действительно дал ответы.** На вопрос «а была хоть одна задача / прогон где ревьюер не просто согласился» агент признал: до этого возврат показывался управляемым тестом. Вариант ослабить модель сначала неверно поняли как замену ревьюера; пользователь уточнила, что имела в виду автора. [S2](sources.md#s2).
11. **Случайное ожидание ошибки → смешанная проба с известным дефектом.** Согласовали подставленную ошибочную первую версию; настоящий ревьюер нашёл ошибку, настоящий автор получил замечание и исправил код, повторное ревью одобрило. Это доказательство передачи замечаний в одном сценарии, а не полностью реальная генерация первой версии и не гарантия качества любых ответов. [S2](sources.md#s2), [отчёт](../architecture-rework/evidence/mixed-review.json); commits `1ffe14a`, `ed97953`.
12. **Попытка дождаться зацикливания → управляемые проверки границ.** Для бесконечных замечаний, отсутствия ответа и остановки нужны воспроизводимые сценарии. Приняты лимиты 3 версии, 7 вызовов, 180 секунд на вызов; лимит рекурсии LangGraph дополняет их. Обнаружение бессмысленного диалога отдельным агентом и точный бюджет токенов не реализованы. [S1](sources.md#s1), [S2](sources.md#s2), [config.ts](../../src/server/config.ts).
13. **«Платные вызовы» → точное описание выбранной авторизации.** Пользователь спросила, зачем обсуждается отдельная оплата при существующем входе Codex. Агент исправил формулировку: выбран вход через ChatGPT и его доступные лимиты; API-ключ проекту не передаётся. Модели при этом работают в облаке. Это описание согласованного способа входа, а не обещание доступности любых моделей или неизменных тарифов. [Переписка 3](conversations/03-mock-tests.md).
14. **Удалить fake-тесты → сохранить и назвать mock.** Сначала пользователь попросила убрать подмены. После объяснения их назначения отменила удаление: «тогда их нужно оставить, тольок назвать mock». Подставленный дефект назван «замоканная версия с намеренной ошибкой»; в смешанных прогонах указано происхождение каждого ответа. Последнее решение действует, раннее отменено. [Переписка 3](conversations/03-mock-tests.md); commit `3ae4edd`.

## Читаемость и переработка

15. **Fastify → Express; затем отдельный пересмотр структуры.** Перенос сохранил HTTP-контракты. Пользователь оспорила смысл отдельного модуля раздачи frontend: выяснили, что Express не диктует структуру, а модуль обслуживает готовую сборку одним сервером. Его удаление не согласовывали; в новой структуре остаётся `routes/frontend.ts`. [S4](sources.md#s4); commits `84e0197`, `de3c2bd`.
16. **Работающий код → код, который автор может объяснить.** Пользователь прямо сказала, что не может свободно ориентироваться и «отвечать за каждую строчку», и усомнилась в смысле тестов. Поэтому отдельно обсудили знакомые правила и архитектуру; первая версия осталась для сравнения, Express стал базой переработки. [S3](sources.md#s3), [S4](sources.md#s4), [S5](sources.md#s5).
17. **Смешанные обязанности клиента → api/hooks/components.** Приняты TanStack Query, отдельные запросы и подписки, отделение серверных данных от отображения. Компоненты показывают данные, hooks управляют их загрузкой и обновлением. [S5](sources.md#s5); commit `63a5a87`.
18. **Много серверных папок → пять групп по обязанностям.** После возражения об избыточности приняты `routes`, `tasks`, `codex`, `code-runner`, `storage`, а также корневые конфиг, запуск и logger. Вопрос о замене проверок на ESLint разобрали: линтер не выполняет тестовые примеры функции, поэтому TypeScript/QuickJS сохранили. [S5](sources.md#s5), [обсуждение сервера](../architecture-rework/server-discussion.md).
19. **Тесты с трудно читаемыми помощниками → явные входы, действия, ожидания.** Сохранили проверяемые сценарии, убрали повтор технической подготовки, разделили этапы пустыми строками. Для каждой новой/переписанной функции потребовали короткое русское объяснение. Размер файлов стал поводом для ревью, без искусственного уплотнения кода. [S5](sources.md#s5), [правила](../architecture-rework/readability.md).
20. **Предложение перенести историю в SQLite → оставить JSONL.** Пользователь явно выбрала JSONL для событий. SQLite сохраняет состояние LangGraph; перенос всей истории в таблицы не приняли. [S5](sources.md#s5), [переписка 3](conversations/03-mock-tests.md).
21. **Поддерживать старые форматы → начинать с чистых данных.** Совместимость со старыми состояниями исключили. После merge пользователь отдельно поручила очистить временные данные; поздний завершённый ответ фиксирует очистку и запуск основной версии на `4317`. Исходники, история Git и авторизация Codex сохранены. Более раннее «область удаления уточняется» уже не описывает итог. [S5, последний turn](sources.md#s5).
22. **Переработка архитектуры → отдельная ветка с последующим merge.** Пользователь согласовала переработку мультиагентами и merge в `main`. Первая версия сохранена в `codex/original-reference`, Express — в `codex/express-migration`; итоговый merge `f537ce4`. [S5](sources.md#s5), [история Git](sources.md#git).
23. **Схема процесса вместо сущностей → уточнение запроса на classDiagram.** Агент неверно понял слово «схема». Пользователь уточнила, что нужны типы и связи из `shared`, и ответ был исправлен. Это подтверждённая коррекция в чате; обещанные там Mermaid-файлы отсутствуют в текущем checkout, поэтому в комплекте они не заявлены готовыми. [S6](sources.md#s6).

## Технические попытки и исправления по журналу разработки

Эти пункты зафиксированы в документах и коммитах разработки. Они не приписываются личному возражению пользователя.

- **Новый TypeScript → закреплённый 5.9.3.** Проверка совместимости показала отсутствие нужного API транспиляции в опробованной версии 7.0.2. Выбрали рабочую версию для QuickJS. [Запись E0](../two-model-loop/decisions.md).
- **`read-only` Codex как предполагаемая изоляция → явное отключение инструментов.** Проба показала возможность чтения за пределами cwd; одного режима `read-only` недостаточно для заявленной границы. Настройки сверили с фактическими возможностями CLI 0.156.1. [Запись E0](../two-model-loop/decisions.md), [адаптер](../../src/server/codex/cli-port.ts).
- **Строгая JSON Schema → неудачный `casesJson` → массив JSON + Zod.** Провайдер отверг `propertyNames`; попытка передавать тесты строкой дала незакрытый JSON. Удалили только неподдерживаемое ограничение, оставили структурированные `cases` и финальную валидацию. [Запись E0](../two-model-loop/decisions.md).
- **PID-файл блокировки → SQLite exclusive transaction.** У прежнего подхода обнаружили гонку удаления устаревшей блокировки. Удерживаемая транзакция ограничивает владельца папки данных и освобождается при завершении процесса. [Запись E0](../two-model-loop/decisions.md), [data-lock.ts](../../src/server/storage/data-lock.ts).
- **Зелёные тесты первой интеграции → исправления независимого ревью.** Исправили смешение режимов real/mock, восстановление уже опубликованного результата, проверку скачивания по одобренному manifest, повторное использование ключа создания и обходы проверок через код гостя. Отдельно восстановили оборванный хвост JSONL. [Журнал и ревью](../two-model-loop/decisions.md); commit `a1ed4e2`.

## Что остаётся под вопросом

- В обсуждениях пользователь сомневалась в независимости ревью похожих моделей, смысле тестов и собственной способности объяснить код. Переработка и смешанная проба отвечают на часть этих вопросов; подтверждения, что все личные сомнения сняты, в просмотренных чатах нет. [S2–S4](sources.md).
- На 28.09 встроенный вход Codex в приложении отсутствует; нужен внешний CLI login. Путь к CLI жёстко задан для Homebrew. Условия и открытая доработка указаны в [хендоффе](handoff.md).
- Полностью реальная демонстрация может пройти без возврата автору. Проверки на известных примерах не доказывают корректность любой сгенерированной функции; после неопределённого облачного исхода нельзя обещать exactly-once.
