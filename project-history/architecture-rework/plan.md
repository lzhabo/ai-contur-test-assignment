Внутри tasks/storage код делится по обязанностям. Отдельный интерфейс или папка для каждой функции не нужны. Fixtures содержат входные данные и явно обозначенные замоканные ответы. Происхождение каждого ответа сохраняется в смешанных сценариях.

## Контракты

1. Routes проверяют запрос, вызывают операцию задачи и возвращают ответ. Ошибка операции содержит смысловой код; HTTP-статус определяет маршрут.
2. Tasks управляют командами и единственной активной задачей. LangGraph определяет порядок шагов и восстановление. Попытка и бюджет сохраняются до вызова модели.
3. Неизвестный исход не запускает скрытый повтор. Сохраняются две разные модели, лимиты, отмена и подтверждение точной версии.
4. Storage сохраняет JSONL перед отправкой события. Проверяются последовательность, уникальность ID, replay/live, неполная последняя строка и restart новых задач.
5. Публикация сверяет version/hash; сохраняются безопасные пути и проверка байтов результата/ZIP. Формат новых файлов можно упростить; код чтения тестовых случаев получает явного владельца формата.
6. Shared содержит только общие схемы. Серверные ports/config уходят к владельцам. Поля режима используют real/mock, настройки сценария — mockScenario и APP_MOCK_SCENARIO.
7. API выполняет запросы; hooks управляют данными, командами и SSE; компоненты отображают. Ключи кеша включают task ID и версию файла. Старый ответ не заменяет новую выбранную задачу. SSE объединяет обновления; polling остаётся резервным способом.
8. Snapshot с меньшим sequence не заменяет более новый; равный sequence допускает обновление состояния. Изменяющие команды автоматически не повторяются, повтор create сохраняет свой ключ.

## Этапы и владельцы

### P0. Подготовка

Координатор проверяет HEAD/status, определяет общие типы/пути, scripts и конфиги. Составляет карту 87 исходных тестов: какое правило проверяется и куда переносится. Все проверяемые сценарии сохраняются; число тестов может измениться при разделении перегруженных сценариев.

Правила закрепляются в AGENTS.md новой ветки, запуск и чтение тестов — в tests/README.md. Исходные версии этих файлов сохраняются. Удаление старых данных выполняется только в уточнённой области и после остановки использующего их процесса.

### P1. Параллельная переработка

| Владелец | Файлы |
| --- | --- |
| Исполнитель сервера | src/server/**, включая config.ts сервера |
| Исполнитель фронтенда | src/client/** и переносимые src/web/** |
| QA | tests/** и карта проверяемых сценариев |
| Координатор | src/shared/**, package/lockfile, корневые конфиги, HTML, AGENTS.md, README, документы задачи |

Пути и интерфейсы определяются до параллельных изменений. Общие файлы имеют одного владельца. Из тестов выносится техническая подготовка; создание задач, решения, остановки и expect остаются видимы. Перегруженные service/HTTP тесты разделяются, однострочные объекты форматируются.

### P2. Интеграция и проверка

- Команда check выполняет lint, typecheck, локальные тесты и build. Команда check:full дополнительно проверяет форматирование, браузерный mock-сценарий, браузерный сценарий настоящего Codex и смешанную live-пробу. Локальный прогон не считается полной приёмкой.
- E2E проходит пользовательский путь с настоящим Codex и свежими данными.
- Restart проверяется на задачах новой версии. Старые базы не импортируются.
- Stop/сбой проверяются управлением настоящими процессами, без подмены ответа. Недостигнутая точка сбоя явно отмечается.
- Модельные тесты последовательны, с ограниченными бюджетом и временем. Скрытых повторов до нужного ответа нет.
- Нет авторизации, сети или доступного лимита — соответствующий тест заблокирован. Автоматического fallback на mock или API key нет.

### P3. Независимые QA и review

После фиксации интегрированной версии QA и reviewer параллельно проверяют поведение, структуру, русские комментарии и читаемость. Исправления выполняются владельцами, затем повторяются затронутые проверки. Команды и фактические результаты записываются в verification.md.

Показать новую ветку/worktree, запуск, карту модулей, доказательства и ограничения. Готовность к приёмке отличается от принятия человеком.

## Mock, реальные и смешанные проверки

Обычные unit/integration тесты выполняют настоящий код модулей и используют mock-адаптер вместо облачной модели, где нужен управляемый ответ. Mock-сценарии сохраняются, включая лимиты, задержки, отмену и ошибки протокола. Они не считаются доказательством облачного подключения.

Реальные проверки вызывают Codex через существующий вход ChatGPT. Полная приёмка включает как воспроизводимые локальные/mock проверки, так и реальные модельные прогоны. Невозможность реального вызова из-за доступа/сети/лимита не компенсируется скрытым переходом на mock.

Смешанная проверка исправления ошибки сохраняется: первая версия называется «замоканная версия с намеренной ошибкой», идентификатор mockedIncorrectCandidate. Ревью и последующее исправление выполняет настоящий Codex. Отчёт отмечает mixed, происхождение первой версии и каждого ответа; число настоящих облачных вызовов учитывается отдельно.

В mock review_once и первая ошибочная версия, и последующее исправление заданы mock-адаптером. В интерфейсе остаётся явное обозначение тестового режима. Реальный ревьюер не обязан выдавать конкретный текст, поэтому недостигнутая ветка реального прогона не считается PASS.

## Приёмка

1. Работает путь создания, авторства, проверки, ревью, решения человека, применения и скачивания.
2. Терминология кода, настроек и актуальных инструкций едина: mock. Замоканные ответы явно обозначены; реальные модельные проверки используют существующую ChatGPT-авторизацию.
3. Новые задачи и история восстанавливаются после restart; неизвестный исход не вызывает скрытого повтора.
4. Для лимитов, идемпотентности, отмены и точной версии есть новые доказательства либо явно отмеченные пробелы проверки.
5. Функции объяснены по-русски; тестовые действия и ожидания читаемы без цепочки скрывающих сценарий helpers.
6. Клиент обрабатывает смену задачи, запоздалые ответы, SSE и ошибки команд.
7. Полная проверка относится к последней версии; старые evidence не подменяют новый прогон.
8. Новая версия начинает с чистыми данными. Миграции старых задач нет; исходники прежних версий сохранены.
