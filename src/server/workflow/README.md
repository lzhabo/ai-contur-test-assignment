# Выполнение задачи

Здесь два модуля с разными обязанностями:

- `graph.ts` — порядок шагов LangGraph, инструкции ролей, ограниченный контекст, проверка лимитов, циклы ревью, паузы `interrupt` и вызовы внешних операций через ports.
- `service.ts` — операции приложения: создать задачу, прочитать её, подтвердить, остановить, возобновить; сериализация команд, один активный запуск, восстановление после старта. HTTP вызывает service; service запускает graph. Сервис не реализует второй движок переходов.

Соседние модули:

- `../codex/cli-port.ts` — настоящие вызовы Codex; `mock-port.ts` — управляемые тестовые ответы.
- `../storage/data-lock.ts` — один процесс-владелец папки данных.
- `../artifacts/` — файлы версий, проверка хешей, публикация.
- `../checks/` — компиляция TypeScript и ограниченное выполнение QuickJS.
- `../events/` — пользовательские события; `../observability/` — диагностические логи узлов и сохранения checkpoint.

Старый `stub.ts` служил только начальной проверке подключения LangGraph и больше не используется; он удалён из рабочего кода.

`prepareAuthor/Reviewer/Applier` намеренно отделены от `callAuthor/Reviewer/Applier`: первая операция сохраняет номер попытки и потраченный бюджет, прежде чем вторая обращается к облаку. Это граница восстановления после аварии. Большинство вызовов асинхронны из-за процессов, файлов и моделей, но сам `async` не сохраняет прогресс: это делают LangGraph и официальный SQLite checkpointer.
