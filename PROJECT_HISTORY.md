Задание выдано 23.09.2026, срок — 03.10.2026, конец дня; часовой пояс в исходнике не указан.

Человек задаёт задачу и принимает решение о результате. Для реализации выбрана одна чистая

## Главные решения

1. **LangGraph + SqliteSaver.** После возражения пользователя отказались от собственного координатора: готовые паузы, checkpoints и продолжение сокращают собственный код. Правила переходов остаются в приложении.
2. **Три роли, две модели.** Автор и применяющий используют `gpt-6-sol`, ревьюер — `gpt-6-luna`. Третья отдельная модель для сохранения не нужна.
3. **Подтверждение конкретной версии.** Автоматическое применение сразу после ревью отклонено пользователем. Сервер проверяет версию и хеши, затем сохраняет одобренные байты.
4. **Браузер и скачиваемые файлы.** Текстовый интерфейс заменён веб-страницей. После уточнения пользовательского пути результатом стали файлы задачи и ZIP. Изменение произвольного существующего проекта не входит в объём.
5. **SQLite для состояния, JSONL для событий.** Перенос всей истории в таблицы отклонён пользователем. Состояние процесса и последовательность наблюдений имеют разные задачи.
6. **Конечные бюджеты.** Приняты 3 версии, 7 вызовов, 180 секунд на вызов. Отдельный агент для распознавания бессмысленного диалога не реализован; управляемые сценарии проверяют остановку по бюджету.
7. **Mock сохранён.** Пользователь отменила первоначальное удаление подмен: они нужны для повторяемых задержек, ошибок и возврата на доработку. Термин `fake` заменён на `mock`.
8. **Известная ошибка для проверки исправления.** В смешанной пробе первая версия замокана с намеренной ошибкой, следующие ревью, исправление и повторное ревью получены от Codex. Это позволяет проверить передачу замечаний без ожидания случайной ошибки автора.
9. **Явные границы модулей.** После переноса Fastify → Express клиент разделён на api/hooks/components, сервер — routes/tasks/codex/code-runner/storage. Причина переработки — трудность навигации и объяснения кода. Мотив первоначального выбора Express в доступной переписке не установлен.
10. **Тесты с видимыми действиями.** Существенные входы, действия и ожидания оставлены в тесте; помощники готовят ресурсы. Русские пояснения объясняют неочевидную логику; после уборки от повторения названий тестов в комментариях отказались.
11. **QuickJS для полученного кода.** Линтер не выполняет примеры функции. TypeScript и изолированный запуск сохранены; экспортированный тест предназначен пользователю, сервер исполняет код через QuickJS.
12. **Отключённые инструменты Codex.** Ранняя проба показала, что `read-only` сам по себе не запрещает чтение за пределами cwd. CLI закреплён на проверенной версии, инструменты отключены явно.
13. **Структурированные тестовые случаи.** Провайдер отверг `propertyNames`; строковый `casesJson` дал незакрытый JSON. Сохранён массив `cases`, удалено неподдерживаемое ограничение схемы, результат проверяется Zod.
14. **Блокировка через SQLite.** PID-файл заменён удерживаемой транзакцией после обнаружения гонки удаления устаревшей блокировки.
15. **Короткая документация.** 29.09 пользователь согласовала заменить папку документов одним файлом истории. Инструкции запуска, устройство системы и команды проверок вынесены в три страницы по ссылкам выше; исходные доказательства остаются в Git.

## Передача

Нужны Node.js 26+, npm; для моделей — сеть, доступ к моделям и свободный лимит Codex.
Приложение проверено на macOS с **Codex CLI 0.156.1 по пути `/opt/homebrew/bin/codex`**.
Путь закреплён в адаптере; одного `codex` в PATH недостаточно. Вход выполняется вне приложения.

```sh
npm ci
/opt/homebrew/bin/codex --version
/opt/homebrew/bin/codex login status
# При отсутствии входа:
/opt/homebrew/bin/codex login
npm start
```

Открыть <http://127.0.0.1:4317>. `npm start` собирает интерфейс. Данные по умолчанию — `.local-data/`.
Одна папка данных принадлежит одному серверу; `APP_DATA_DIR` и `APP_PORT` задают отдельный запуск.
Остановка — Ctrl+C; повтор той же команды открывает сохранённые задачи. Режим по умолчанию — real.

Запуск с заранее заданным исправлением:

```sh
APP_CODEX_MODE=mock APP_MOCK_SCENARIO=review_once APP_DATA_DIR=.local-data/demo-mock APP_PORT=4319 npm start
```

Выбрать «Объединить интервалы», запустить агентов, изучить ревью и файлы, подтвердить и скачать ZIP.
В этом mock-сценарии автор, ревьюер и исправление заданы адаптером. Настоящие вызовы расходуют лимит аккаунта.

| Папка | Ответственность |
| --- | --- |
| `src/client/{api,hooks,components,workflow}` | Запросы, подписки, интерфейс и отображение процесса |
| `src/server/tasks/` | Команды, граф, роли и восстановление |
| `src/server/{routes,codex,code-runner,storage}` | HTTP/SSE, Codex, проверки кода и хранение |
| `src/shared/` | Общие схемы и примеры |
| `tests/` | Локальные, браузерные и отдельно запускаемые модельные проверки |

Проверка перед передачей: `npm run check`; остальные команды и происхождение ответов — в [tests/README.md](tests/README.md).
Открытые вопросы: вход в UI и настройка пути CLI отсутствуют; другие ОС не проверены; после аварии backend
может остаться процесс Codex. Одна активная задача, чистые функции, без сети, файлов и сторонних зависимостей.
В обсуждениях 26–27.09 автор подняла вопросы независимости ревью, достаточности тестов и понятности кода.
Одно успешное исправление не доказывает корректность любых ответов моделей.

## Демонстрация — 20 минут

До встречи выполнить локальные проверки, проверить вход Codex, открыть код и этот журнал.
Для реального показа использовать отдельную папку: `APP_DATA_DIR=.local-data/demo-real npm start`.
Второй сервер — mock-команда из раздела передачи. Каждая новая репетиция использует отдельные каталоги.

| Время | Действие |
| --- | --- |
| 0–3 мин | Показать роли и ограничения, запустить реальную задачу «Объединить интервалы». |
| 3–6 мин | Открыть события автора/ревьюера, время и счётчики; объяснить отсутствие ответа и лимиты. |
| 6–9 мин | Посмотреть код, тесты и замечания; обновить страницу перед решением, подтвердить версию, скачать ZIP. |
| 9–12 мин | На mock-сервере показать `review_once`: ошибку, замечание и исправление; отклонить результат. |
| 12–15 мин | Показать граф, проверку версии в `commands.ts`, сохранение в `storage/local-store.ts`. |
| 15–17 мин | Перезапустить свой сервер, открыть сохранённую задачу; объяснить отдельную проверку аварийного сбоя. |
| 17–20 мин | Показать Git, два решения и переписки; оставить время на вопросы и вмешательство. |

Если к шестой минуте реальный вызов не завершился, остановить его, назвать фактический исход и показать ZIP
на mock-сервере. Реальный ревьюер может одобрить первую версию; возврат не гарантирован.
Для демонстрации молчания отдельно использовать `APP_MOCK_SCENARIO=no_response`, затем остановить задачу.
После показа записать ID задач, режим real/mock/mixed и фактические исходы. Сам показ пока не проведён.
