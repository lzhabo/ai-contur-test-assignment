# Контур

Локальное веб-приложение для разработки одной TypeScript-функции. Автор готовит код, ревьюер на другой модели проверяет его, а третий агент инициирует сохранение одобренной версии после решения пользователя. LangGraph управляет процессом; официальный SqliteSaver сохраняет состояние, файлы лежат в отдельной папке каждой задачи.

**Статус:** приложение реализовано; независимые проверки типов, сборка и 62 теста прошли, замечания ревью исправлены. Реальный прогон дошёл до подтверждения пользователя; третий реальный агент пока не проверен в полном сценарии. Приёмка человеком ещё не проведена. [Инструкция передачи](tasks/two-model-loop/delivery/handoff.md), [отчёт проверок](tasks/two-model-loop/verification.md).

## Запуск

Проверяемая среда: macOS, Node.js **26.9.0**, npm **11.19.1**, Codex CLI **0.156.1**. Вход Codex должен быть выполнен через ChatGPT (`codex login status`). Модели по умолчанию: автор и применяющий — `gpt-6-sol`, ревьюер — `gpt-6-luna`. Отдельный API key приложению не нужен.

```sh
npm ci
npm start
```

Открыть <http://127.0.0.1:4317>. `npm start` собирает интерфейс и запускает один локальный backend. Закрытие вкладки не прекращает работу backend. Для остановки сервера — Ctrl+C; для продолжения — та же команда с той же папкой данных.

Адаптер привязан к проверенной версии Codex: неизвестная версия отклоняется, поскольку конфигурация отключения инструментов может измениться. Перед обновлением нужно повторить проверки адаптера, а не удалять контроль версии. Реальные вызовы используют лимиты аккаунта Codex.

## Пользовательский путь

1. Нажать «Новая задача», описать функцию или выбрать один из трёх примеров и отредактировать текст.
2. Запустить агентов и наблюдать сообщения, проверки и доработки.
3. Просмотреть функцию, тесты и ревью; подтвердить или отклонить конкретную версию.
4. После подтверждения получить файлы, путь к папке результата и ZIP.

Область первой версии: чистые синхронные функции, JSON-входы/выходы, без сети, файлов, импорта сторонних библиотек и изменения существующего проекта. Проверки выполняются в QuickJS без host API, с лимитами времени и памяти. Модели не получают архив переписки и инструменты доступа к файлам.

## Данные

```text
.local-data/
  checkpoints.sqlite
  tasks/<task-id>/
    revisions/<version-id>/   # неизменяемые версии и manifest
    result/                  # только подтверждённые файлы
    events.jsonl             # наблюдаемые события
```

Точную структуру вспомогательных файлов определяют модули приложения. `.local-data/` исключена из Git. Для переноса истории нужны и SQLite, и папки задач; для выдачи результата достаточно папки `result` или ZIP. Удалять данные во время работы сервера нельзя. Для чистого запуска укажите новую пустую папку вместо удаления прежней:

```sh
APP_DATA_DIR=.local-data/fresh-run APP_PORT=4318 npm start
```

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

Тестовые сценарии с имитацией облака запускаются явно; они не доказывают доступ к реальным моделям:

```sh
APP_CODEX_MODE=fake APP_FAKE_SCENARIO=review_once APP_DATA_DIR=.local-data/demo-review npm start
```

Сценарии: `happy`, `review_once`, `review_loop`, `no_response`, `slow`. По умолчанию используется `real`. Режим задачи сохраняется вместе с состоянием и показан в интерфейсе. Пользователь не должен принимать fake-прогон за настоящие ответы моделей.
