# Как работает «Контур»

Приложение разрабатывает одну чистую синхронную TypeScript-функцию с JSON-входом и выходом. Автор, ревьюер и применяющий агент — три роли. Автор и ревьюер работают на разных моделях. В каждый момент допускается одна незавершённая задача.

## Порядок выполнения

| Шаг | Действие | Следующий шаг |
| --- | --- | --- |
| Создание | Express проверяет текст, сохраняет индекс задачи и начальное состояние графа. | Автор |
| Автор | Получает задание, текущую версию и последние замечания. Возвращает код и тестовые случаи. Сервер сохраняет новую версию. | Проверки |
| Проверки | TypeScript проверяет типы; QuickJS исполняет тестовые случаи автора. | Ревью |
| Ревью | Другая модель получает точную версию и результаты проверок. | Замечания → автор; одобрение и пройденные проверки → решение человека |
| Решение человека | Граф ждёт подтверждения конкретных `versionId` и `manifestHash`. | Подтверждение → применение; отказ → остановка |
| Применение | Агент возвращает запрос на сохранение одобренной версии. Сервер сверяет идентификатор, хеши и байты файлов. | Готовый результат и ZIP |

Граф: [agent-loop.ts](../src/server/tasks/agent-loop.ts). Действия шагов: [agent-steps.ts](../src/server/tasks/agent-steps.ts). Схема пользовательского потока — в [README](../README.md#поток-работы).

## Состояния и остановка

| Состояние | Значение |
| --- | --- |
| `preparing` | Задача создана, выполнение подготовлено. |
| `author`, `checking`, `review`, `applying` | Выполняется соответствующий шаг. |
| `awaiting_approval` | Версия прошла проверки и ревью; требуется решение человека. |
| `unknown_outcome` | Вызов не получил достоверного завершения. Повтор возможен только по команде пользователя. |
| `completed` | Одобренные файлы сохранены и проверены. |
| `stopped` | Пользователь остановил задачу, отклонил версию или исчерпан бюджет. Причина сохраняется. |
| `error` | Обнаружена известная ошибка проверки, ответа или целостности результата. |

Перед каждым обращением к модели отдельный шаг резервирует попытку и увеличивает счётчик. LangGraph сохраняет его в SQLite до внешнего вызова. Лимит — 3 версии и 7 вызовов на всю задачу, включая повтор неизвестного вызова и применяющего агента. Один вызов ограничен 180 секундами. Через 30 секунд интерфейс показывает длительное ожидание.

Таймаут или потеря процесса могут оставить неизвестный исход: модель могла обработать запрос. Приложение сохраняет `unknown_outcome` и ждёт явного решения. Принудительный повтор расходует новую попытку. Остановка отменяет текущий вызов; начавшаяся публикация завершается до фиксации остановки.

## Что получает модель

Каждый вызов получает инструкции роли, задание, текущую версию, последние замечания и результаты проверок. Применяющий агент получает также решение человека. Прошлые версии и полная история событий в контекст не добавляются. Размер контекста ограничен 96 КиБ.

Codex вызывается отдельным процессом во временной папке через `codex exec`. Адаптер проверяет версию CLI, ожидаемый формат ответа и выбранную модель, отключает локальные инструменты. Отмена завершает группу процессов. Промпты ролей и сбор контекста находятся в [role-call.ts](../src/server/tasks/role-call.ts), протокол CLI — в [cli-port.ts](../src/server/codex/cli-port.ts).

## Проверки кода

Проверяются синхронность, наличие именованного экспорта заданной функции и отсутствие импортов. На верхнем уровне допускаются объявления функций; единственность экспорта не проверяется. TypeScript проверяет типы. QuickJS исполняет функцию отдельно от Node.js, без доступа к сети и файлам хоста; сравнивает результат с ожидаемым и проверяет изменение аргументов. На проверки отводится 5 секунд и 64 МиБ памяти.

Приложение использует случаи автора, проверки контракта и ревью. Фиксированные независимые случаи `mergeIntervals` подключаются в интеграционных тестах репозитория и смешанной модельной пробе. Успешный прогон подтверждает только проверенные входы.

Размер задания — до 8000 символов; суммарный размер кода и файла тестов одной версии — до 64 КиБ. Общие значения ограничений находятся в [limits.ts](../src/shared/limits.ts), исполняемые бюджеты — в [config.ts](../src/server/config.ts).

## Хранение и восстановление

| Файл или каталог в папке данных | Назначение |
| --- | --- |
| `tasks-index.json` | Список задач, исходные тексты и ключи повторного создания. С него начинается восстановление. |
| `checkpoints.sqlite` | Состояние LangGraph, попытки, бюджеты и точка продолжения. |
| `tasks/<id>/events.jsonl` | История событий задачи с последовательными номерами. |
| `tasks/<id>/revisions/<version>/` | Неизменяемые `solution.ts`, `solution.test.ts` и `manifest.json` с хешами. |
| `tasks/<id>/result/` | Одобренные файлы, manifest и запись публикации. |
| `.owner-lock.sqlite` | Блокировка: одной папкой данных владеет один сервер. |
| `server-events.jsonl` | Технические логи шагов, сохранения состояния и ошибок. |

История записывается на диск до отправки события в браузер. Повторная доставка после переподключения использует курсор события. SQLite хранит состояние исполнения, JSONL — события для интерфейса. Копия файлов в `result/` фиксирует одобренный результат независимо от черновиков.

При запуске сервер читает индекс и состояния задач:

- Завершённые задачи доступны для просмотра; байты результата сверяются с одобренной версией.
- Ожидание решения человека сохраняется.
- Вызов модели, результат которого не попал в checkpoint, переводится в `unknown_outcome`.
- Если публикация успела записать результат до сбоя, сервер проверяет его и восстанавливает завершение без повторного вызова модели.
- Остальные незавершённые шаги продолжаются с сохранённой точки.
- Задачу другого режима (`real`/`mock`) можно просматривать; для продолжения нужен её исходный режим.

Для переноса задач остановите сервер и перенесите **всю папку данных**, включая скрытые и служебные файлы SQLite. Закрытие вкладки оставляет сервер работающим. `Ctrl+C` завершает сервер штатно. Логика восстановления — [recovery.ts](../src/server/tasks/recovery.ts).

## Интерфейс и API

Компоненты React получают данные через hooks. `client/api` выполняет HTTP-запросы и подключает SSE; TanStack Query хранит ответы. SSE обновляет состояние экрана, резервный опрос восстанавливает данные после разрыва. Ответ с меньшим номером события не заменяет более свежий.

Изменяющие запросы автоматически не повторяются. Создание задачи использует ключ идемпотентности; подтверждение содержит ID решения, версии и хеш. Сервер сериализует команды и отклоняет устаревшее подтверждение. Скачивание разрешено только после проверки файлов текущей версии; ZIP требует завершённой публикации.

| Модуль | Обязанность |
| --- | --- |
| `server/routes` | HTTP, SSE и выдача собранного интерфейса. |
| `server/tasks` | Команды, состояния, граф и восстановление. |
| `server/codex` | Настоящий CLI и управляемые mock-ответы. |
| `server/code-runner` | TypeScript и выполнение в QuickJS. |
| `server/storage` | Индекс, события, SQLite и файлы версий. |
| `shared` | Общие схемы API, ограничения и примеры; без серверных зависимостей. |

Проверяемые сценарии и команды — в [tests/README.md](../tests/README.md).
